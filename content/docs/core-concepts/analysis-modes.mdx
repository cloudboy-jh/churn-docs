## Full Analysis

Analyzes all files in your repository (excluding ignored patterns).

```bash
churn run
```

### When to use

- First-time analysis
- Pre-release quality checks
- Comprehensive code reviews
- Major refactoring projects

### Cost implications

Analyzes entire codebase, highest API usage

## Staged Analysis

Analyzes only files in your Git staging area.

```bash
churn run --staged
```

### When to use

- Daily development workflow
- Before commits
- Quick quality checks
- Cost-conscious analysis

### Benefits

80-90% cost savings compared to full analysis

## File-Specific Analysis

Analyzes specific files or patterns.

```bash
churn run --files "src/components/**/*.tsx"
```

### When to use

- Targeting specific modules
- Reviewing changed files
- Analyzing new features
- Debugging specific areas

### Examples

```bash
# Analyze all TypeScript files
churn run --files "**/*.ts"

# Analyze specific directory
churn run --files "src/auth/**/*"

# Multiple patterns
churn run --files "src/components/**/*.tsx" --files "src/hooks/**/*.ts"
```

## Choosing the Right Mode

| Use Case | Recommended Mode | Cost Impact |
|----------|-----------------|-------------|
| Daily development | Staged | 10-20% of full |
| Pre-commit checks | Staged | 10-20% of full |
| Feature review | File-specific | 20-40% of full |
| Release prep | Full | 100% |
| Initial analysis | Full | 100% |
