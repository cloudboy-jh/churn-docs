## Workflow Phases

### 1. Initialization

Churn starts by:
- Detecting your Git repository
- Loading global and project-specific configuration
- Determining which files to analyze based on mode

### 2. File Collection

Depending on the mode:
- **Full**: Collects all repository files
- **Staged**: Collects only files in Git staging area  
- **Pattern**: Collects files matching the specified pattern

All files are then filtered against ignore rules.

### 3. Caching Layer

Before sending files to the AI model:
- Each file is hashed (SHA-256)
- Hash is checked against the cache
- Cache hits reuse previous results (70% cost savings)
- Cache misses proceed to analysis

### 4. AI Analysis

Files without cached results are:
- Batched for efficient processing
- Sent to your selected AI model
- Processed with context about your codebase
- Returned with categorized suggestions

### 5. Results Processing

Raw AI responses are:
- Parsed and validated
- Categorized by type (refactor, bug, optimization, etc.)
- Assigned severity levels (high, medium, low)
- Stored in local database

### 6. Interactive Review

The `churn review` command lets you:
- Navigate through suggestions
- View detailed explanations and code diffs
- Accept or reject each suggestion
- Apply changes interactively

### 7. Export & Reporting

Finally, `churn export` generates:
- **JSON**: For programmatic access and CI/CD
- **Markdown**: For human-readable reports
- **Git Patch**: For applying changes with Git

## Command Sequence

Typical usage pattern:

```bash
# 1. Select AI model (one-time setup)
churn model

# 2. Run analysis
churn run --staged

# 3. Review suggestions interactively
churn review

# 4. Export results
churn export
```

## Optimization Tips

- Use `--staged` for daily development (80-90% cost savings)
- Run full analysis before releases
- Cache persists for 30 days automatically
- Batch multiple files for better performance
